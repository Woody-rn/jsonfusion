# jsonfusion — Требования

## 1. Что это

Интерактивный веб-инструмент для мержа двух JSON-файлов в третий.
Пользователь настраивает правила через web-интерфейс, видит несовпавшие
записи, правит вручную, получает результат.

**Деплой:** `jsonfusion.npepub.ru` (поддомен портфолио).

**Пользователь:** Java-разработчик / аналитик / любой, кто работает с
JSON-выгрузками. Инструмент локальный для одного пользователя (без авторизации).

---

## 2. Функциональные требования

### 2.1. Вход / выход

- **Вход:** два JSON-файла.
- **Выход:** третий JSON-файл.
- **Формат:** массив плоских объектов с полями вида `name`, `status`, `updatedAt`.
- **Входные файлы не мутируем.**
- **Лимит размера:** 5 МБ на файл.

### 2.2. Анализ полей

- Система читает оба файла и показывает:
    - поля, которые есть **в обоих** (пересечение),
    - поля **только в F1**,
    - поля **только в F2**.
- Для каждого поля — **ровно одна роль** (см. 2.3).
- Роль **всегда есть**. Состояния «ничего не выбрано» нет.

### 2.3. Роли полей

| Роль | Смысл |
|------|-------|
| `Якорь` (ANCHOR) | По этому полю сопоставляем записи. **Ровно один** на прогон. |
| `Приоритет F1` (PRIORITY_F1) | Значение для результата берём из файла 1. |
| `Приоритет F2` (PRIORITY_F2) | Значение для результата берём из файла 2. |
| `Удалить` (DELETE) | Поля нет в результате вообще (глобально). |

**Дефолты:**
- Поле есть в обоих → `Приоритет F1`.
- Поле только в F1 → `Приоритет F1`.
- Поле только в F2 → `Приоритет F2`.

**Ограничения:**
- `Якорь` и `Удалить` — взаимоисключающие.
- `Приоритет` и `Удалить` — взаимоисключающие.
- `Якорь` — только одно поле.
- Если поле-якорь выбрано в F1 → во втором файле оно **заблокировано**.

### 2.4. Условие приоритета

Для полей с ролью `Приоритет F1` / `Приоритет F2` доступна доп. опция:

| Режим | Смысл |
|-------|-------|
| `ALWAYS` | Перезаписывать всегда (по умолчанию). |
| `IF_EQUALS` | Перезаписывать, только если текущее значение (в неприоритетном файле) равно указанному. |

**Правила `IF_EQUALS`:**
- Пользователь вводит значение в текстовое поле.
- Пустое поле = «null / пустая строка / ключа нет».
- Сравнение **без учёта регистра**.
- Пробел как значение отображается видимым символом (␣).

### 2.5. Якорь — настройки сравнения

- Якорь — **одно поле**, не составной.
- Сравнение значений якоря:
    - **без учёта регистра** (галочка, вкл по умолчанию),
    - **trim + collapse пробелов** (галочка, вкл по умолчанию).
- Пробелы **внутри** слова значимы (`ООО Ромашка` ≠ `ОООРомашка`).
- Значение якоря в результат — **из F1, как есть** (оригинал, с регистром).

### 2.6. Новые поля

- Можно добавить поле в результат:
    - **имя**,
    - **значение по умолчанию**.
- Применяется **ко всем** записям результата.

### 2.7. Merge (авто)

- **Авто-матч только по уникальным якорям с обеих сторон.**
- Если значение якоря дублируется в F1 или F2 → все записи с этим якорем уходят в несовпавшие.
- Совпавшие 1:1 → сливаются по правилам (2.3, 2.4).

### 2.8. Несовпавшие

**Три типа несовпавших:**

| Тип | Смысл |
|-----|-------|
| `ONLY_IN_LEFT` | Есть в F1, нет в F2. |
| `ONLY_IN_RIGHT` | Есть в F2, нет в F1. |
| `DUPLICATE` | Якорь дублируется в F1 или F2. |

**UI:**
- Два списка: несовпавшие F1, несовпавшие F2.
- Пометка-иконка рядом с записью (тип).
- Фильтр «показать только дубликаты».

**Действия:**
- **Ручное сопряжение:** метка (1, 2, 3…) на одну левую + одну правую → пара. **Строго 1:1.**
- **Игнорирование:** крестик рядом с записью.
- **Массовое:** «игнорировать все» / «выбрать все».

**Результат:**
- Проигнорированные в результат **не идут**.
- Непарные и неигнорированные — **идут как есть**.
- Пары обрабатываются по правилам (2.3, 2.4), как matched.

### 2.9. Финализация

- Сборка третьего JSON с учётом всех решений.
- Скачивание файла.

## 3. Нефункциональные требования

### 3.1. Сессии

- Хранилище: **Caffeine in-memory**.
- TTL idle: **15 минут** для всех статусов.
- Абсолютный TTL: 2 часа.
- После finalize: **удалять сразу**.
- Лимит сессий в кэше: **100**.
- `sessionId` = UUID v4.

### 3.2. Вкладки

- Каждая вкладка = **своя сессия** (`sessionStorage`).
- Никаких конфликтов между вкладками.

### 3.3. Безопасность

- **Без авторизации.**
- Один инстанс приложения.
- Rate limiting — не в MVP.

### 3.4. UI/UX

- Wizard из шагов:
    1. Загрузка файлов.
    2. Настройка полей.
    3. Несовпавшие.
    4. Результат.
- Стек: React + TypeScript + Vite + Chakra UI + Zustand.

### 3.5. Совместимость

- Современные браузеры (Chrome, Firefox, Safari, Edge — последние версии).

---

## 4. Ограничения и допущения

- **JSON:** массив плоских объектов.
- **Поля:** плоские, без вложенности.
- **Массивы внутри записи:** сравниваются как значение целиком.
- **Имена полей:** строгое сравнение (`Name` ≠ `name`).
- **Якорь:** один, не составной.
- **Пары несовпавших:** только 1:1.
- **Один инстанс**, in-memory сессии.

---

## 5. Не входит в MVP

- Авторизация / многопользовательность с логином.
- Составной якорь (по нескольким полям).
- N:M пары несовпавших.
- Умные дефолты приоритета (всегда F1, пользователь правит).
- Вложенные JSON / массивы внутри полей (глубокая обработка).
- Redis / распределённые сессии / масштабирование.
- История операций.
- Rate limiting.
- SSE / WebSocket прогресс.
- Загрузка файлов > 5 МБ.
- Поддержка других корневых структур (объект с массивом, вложенные пути, массивы в записях).

## 6. Статусы сессии

| Статус | Описание |
|--------|----------|
| `CREATED` | Создана, файлов нет |
| `FILES_UPLOADED` | Файлы загружены, конфиг не задан |
| `CONFIGURED` | Конфиг задан, merge не запущен |
| `MERGED` | Merge выполнен, несовпавшие не обработаны |
| `UNMATCHED_RESOLVED` | Несовпавшие обработаны, финал не собран |
| `FINALIZED` | Результат собран, можно скачивать |

**Переходы:**

```
CREATED             → FILES_UPLOADED       (POST /files)
FILES_UPLOADED      → CONFIGURED           (PUT /config)
CONFIGURED          → MERGED               (POST /merge)
MERGED              → UNMATCHED_RESOLVED   (PUT /unmatched/decisions)
UNMATCHED_RESOLVED  → FINALIZED            (POST /finalize)
```
