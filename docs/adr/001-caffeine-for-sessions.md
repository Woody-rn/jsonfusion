# ADR-001: Caffeine для хранения сессий

## Контекст

Сессии нужно хранить in-memory, с TTL по бездействию и лимитом по размеру.
Рассматривали: `ConcurrentHashMap`, Caffeine, Guava Cache, Redis.

## Решение

Используем **Caffeine**.

## Обоснование

- TTL из коробки (`expireAfterAccess`).
- Лимит по размеру (`maximumSize`).
- Не тащим внешнюю инфраструктуру (Redis) для MVP.
- Легко заменить на Redis позже — интерфейс `SessionStore`.

## Последствия

- Сессии теряются при рестарте приложения (приемлемо для MVP).
- Не масштабируется на несколько инстансов (приемлемо для MVP).
